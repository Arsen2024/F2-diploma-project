# 1. Назва кваліфікаційного проєкту

UA: Розробка архітектури ігрових систем управління процесом для нелінійної survival horror гри на Unreal Engine 5

EN: Development of Gameplay Systems Architecture for a Nonlinear Survival Horror Game on Unreal Engine 5 

# 2. Актуальність та проблематика

Розробка сучасної survival horror гри з нелінійною структурою проходження потребує надійної програмної архітектури, здатної підтримувати узгоджену роботу кількох незалежних ігрових систем: керування персонажем, поведінку неігрових істот, збереження прогресу, активацію сюжетних подій та інтерфейс користувача. Складність зростає через нелінійність проходження — гравець може повертатися до вже відвіданих локацій, а стан гри повинен коректно зберігатися й відновлюватися в довільний момент без порушення логічної цілісності світу.

Окремою інженерною проблемою є побудова слабко зв'язаної архітектури, що дозволяє незалежну роботу та розширення систем без жорсткого зв'язування компонентів між собою. Це особливо важливо для поведінки NPC/істот, чия реакція на дії гравця має залишатися некатегоричною (не завжди однозначно "ворожа" чи "дружня") — таку поведінку складно реалізувати через прості умовні конструкції, що вимагає використання повноцінних поведінкових дерев та станових машин.
Додатково, ігрова логіка повинна коректно взаємодіяти з іншими технічними підсистемами проєкту — динамічним освітленням, візуальними ефектами аномалій та звуковим супроводом, — оскільки саме тригери й скриптовані події є точкою інтеграції між програмною логікою та атмосферними ефектами гри.

Інженерна складність проблеми полягає в необхідності:

- розробити архітектуру контролера гравця та системи взаємодії з об'єктами оточення;
- реалізувати систему штучного інтелекту істот на основі поведінкових дерев (Behavior Trees) та станових машин, здатну підтримувати кілька категорій поведінки, включно з неоднозначною реакцією на дії гравця;
- реалізувати систему збереження та відновлення стану гри (чекпоінти), що коректно фіксує позицію гравця, прогрес подій та стан активованих тригерів;
- побудувати гнучку систему тригерів і скриптованих подій на основі подієво-орієнтованого підходу, здатну активувати як ігрову логіку, так і суміжні технічні підсистеми (освітлення, VFX, звук) без прямого зв'язування компонентів;
- реалізувати інтерфейс користувача (UI/HUD), що відображає стан гравця та прогрес без порушення атмосфери жанру;
- забезпечити стабільну продуктивність під час одночасної роботи всіх перелічених систем на великих локаціях;
- організувати структуру проєкту та систему контролю версій для стабільної командної розробки.

Таким чином, проєкт спрямований на вирішення інженерної проблеми побудови надійної, розширюваної та продуктивної архітектури ігрових систем для нелінійного survival horror проєкту на Unreal Engine 5.

# 3. Ідея проєкту

Проєктується та реалізується інтерактивна survival horror гра від першої особи, події якої відбуваються у системі підземних катакомб, що приховують забутий магічний підземний світ.
За сюжетом, близький друг головного героя зникає під час дослідження катакомб. Після припинення офіційних пошукових робіт герой самостійно вирушає на його пошуки. У підземеллі він знаходить залишене спорядження та останню записку з попередженням не продовжувати рух. Після цього внаслідок обвалу тунелю шлях назад стає недоступним, і герой змушений просуватися вглиб, де поступово виявляє існування прихованої магічної цивілізації та її мешканців — розумних істот з неоднозначною поведінкою, від ворожої до умовно дружньої.

Архітектура програмного рішення передбачає розділення основних ігрових підсистем (контролер гравця, AI істот, система збереження стану, система тригерів та скриптованих подій, UI/HUD) на незалежні, слабко зв'язані компоненти, що взаємодіють через визначені інтерфейси та систему подій Unreal Engine. Ці підсистеми виступають також точкою технічної інтеграції з суміжними напрямками розробки — динамічним освітленням, візуальними ефектами середовища та звуковим супроводом, — забезпечуючи цілісність атмосфери гри без порушення архітектурної незалежності систем.

# 4. Опис функціоналу

4.1 Контролер гравця

- Реалізація руху персонажа від першої особи (ходьба, присідання, взаємодія з об'єктами оточення) з урахуванням специфіки horror-жанру.
- Система взаємодії з предметами та інтерактивними елементами рівня через трасування променя (line trace) та інтерфейси взаємодії.
- Керування станом персонажа (здоров'я, витривалість, ефекти від впливу середовища).

4.2 Штучний інтелект істот

- Побудова поведінкових дерев (Behavior Trees) та станових машин для кількох категорій істот з відмінною логікою реакції (ворожа, нейтральна, умовно дружня).
- Реалізація системи сприйняття (AI Perception) — зір, слух — для формування реакції на дії гравця залежно від контексту.
- Механізм динамічної зміни поведінкового стану істоти в реальному часі як основа для неоднозначного, важкопрогнозованого сприйняття NPC гравцем.

4.3 Система збереження та чекпоінтів

- Проєктування структури даних стану гри: позиція гравця, прогрес подій, стан активованих тригерів та істот.
- Реалізація автоматичних та ручних точок збереження, інтегрованих з тригерами рівня.
- Коректне відновлення стану світу при завантаженні збереження без розсинхронізації між підсистемами.
- Розробка механізму версіонування структури збережених даних (save data versioning) для забезпечення сумісності при зміні схеми стану в процесі розробки.

4.4 Система тригерів і скриптованих подій

- Розробка універсального механізму тригерів (об'ємні зони, взаємодія з об'єктами, умовні події) для активації сюжетних моментів.
- Побудова подієво-орієнтованої системи комунікації між тригерами, AI та станом гравця, що слугує також точкою виклику суміжних технічних ефектів (освітлення, VFX, звук) без прямої залежності між класами.

4.5 UI/HUD

- Проєктування та реалізація мінімалістичного інтерфейсу: індикатори стану персонажа, підказки взаємодії, меню збереження/завантаження.

4.6 Оптимізація

- Профілювання продуктивності ігрової логіки та AI засобами Unreal Insights.
- Оптимізація частоти опитування AI Perception та логіки поведінкових дерев для зменшення навантаження на CPU.
- Налаштування рівнів деталізації логіки (LOD для AI) залежно від відстані до гравця.

4.7 Контроль версій, CI/CD та організація проєкту

- Налаштування системи контролю версій (Git/Perforce з підтримкою бінарних asset-файлів Unreal Engine) для командної розробки.
- Формування структури проєкту та угод іменування, що мінімізують конфлікти при паралельній роботі над Blueprint-класами.
- Побудова CI/CD пайплайна (GitHub Actions + Unreal Automation Tool) для автоматичної збірки проєкту та запуску автоматизованих тестів при внесенні змін до репозиторію.

4.8 Тестування та забезпечення якості

- Розробка автоматизованих тестів (Unreal Automation Testing Framework) для перевірки коректності станових переходів AI та цілісності даних системи збереження.
- Функціональне тестування сценаріїв збереження/відновлення стану на різних етапах проходження.

4.9 Технічна реалізація суміжних ефектів

У межах проєкту також виконується технічна реалізація ефектів, що інтегруються з описаною архітектурою через систему тригерів:

- динамічне освітлення сцен та пост-процес ефекти (Lumen, Unreal Engine 5);
- візуальні ефекти аномалій та світних елементів середовища (Niagara, матеріали);
- технічна інтеграція звукового супроводу (просторовий звук, реверберація, активація через Blueprint/MetaSounds).


# 5. Попередній інструментарій та технологічний стек

Мови програмування

- C++ — реалізація базових класів та продуктивних компонентів (базові класи контролера гравця, AI-контролерів, систем збереження), де це необхідно для продуктивності або доступу до низькорівневого API Unreal Engine.
- Blueprints (візуальна мова скриптування Unreal Engine) — основна мова реалізації ігрової логіки, поведінкових дерев, тригерів, скриптованих подій та UI, що забезпечує швидку ітерацію та зручність командної розробки.

Архітектурні патерни

- Event-Driven Architecture — подієво-орієнтована взаємодія між тригерами, AI та іншими підсистемами без жорсткого зв'язування компонентів (Event Dispatchers/Delegates Unreal Engine).
- Component-Based Architecture — розподіл функціоналу персонажа та істот на незалежні компоненти (Actor Components).
- State Pattern / Behavior Tree Pattern — реалізація поведінки істот через станові машини та поведінкові дерева.
- Interface Pattern — взаємодія між підсистемами через Blueprint Interfaces для зменшення прямих залежностей між класами.

Фреймворки та движок

- Unreal Engine 5 — основний движок розробки.
- AI Perception, Behavior Tree, Blackboard — підсистема штучного інтелекту.
- Lumen — динамічне освітлення сцен.
- Niagara — система візуальних ефектів (VFX).
- MetaSounds — технічна реалізація звукового супроводу.
- Enhanced Input System — обробка введення гравця.

Зберігання даних

Проєкт не використовує класичну серверну базу даних, оскільки є одноосібною (offline) грою. Зберігання прогресу реалізується засобами:

- Unreal SaveGame System — серіалізація стану гри (позиція гравця, прогрес подій, стан тригерів) у локальні бінарні файли збереження.

DevOps-інструменти

- Git (з розширенням Git LFS для бінарних asset-файлів Unreal Engine) або Perforce — система контролю версій для командної розробки.
- GitHub/GitLab — хостинг репозиторію, трекінг задач та issue-менеджмент.
- GitHub Actions + Unreal Automation Tool (UAT) — автоматизація збірки проєкту та запуску тестів (CI/CD).
- Unreal Insights — профілювання продуктивності під час розробки та оптимізації.
- Unreal Automation Testing Framework — автоматизоване тестування ігрової логіки.
